### Q1. What is the Java Module System (JPMS) introduced in Java 9?
**Difficulty:** Hard | Senior
**Type:** Theory + Scenario

**Answer:**
The Java Platform Module System (JPMS), introduced in Java 9 (Project Jigsaw), adds a module layer above packages. A **module** is a named, self-describing set of packages with explicit dependencies and exports.

Key goals:
- **Strong encapsulation:** packages not exported are inaccessible even via reflection (without `--add-opens`)
- **Reliable configuration:** module dependencies declared explicitly — no more classpath hell
- **Scalability:** create custom JRE images with only required modules (`jlink`)

**`module-info.java` syntax:**
```java
// module-info.java (must be in src/main/java root, not in a package)
module com.catmanscodes.app {
    requires java.base;           // implicit, always included
    requires java.sql;            // explicit dependency
    requires transitive java.logging;  // transitive — consumers also get this
    
    exports com.catmanscodes.api;           // accessible to all modules
    exports com.catmanscodes.internal to com.catmanscodes.test; // qualified export
    
    opens com.catmanscodes.model;           // allows deep reflection (e.g., Hibernate)
    opens com.catmanscodes.model to org.hibernate.orm.core; // qualified opens
    
    uses com.catmanscodes.spi.PaymentService;    // ServiceLoader consumer
    provides com.catmanscodes.spi.PaymentService // ServiceLoader provider
        with com.catmanscodes.impl.StripePaymentService;
}
```

**Example — reading module info at runtime:**
```java
Module module = String.class.getModule();
System.out.println(module.getName());      // java.base
System.out.println(module.isNamed());      // true

// Unnamed module (classpath code)
Module unnamed = Main.class.getModule();
System.out.println(unnamed.isNamed());     // false (classpath = unnamed module)
```

**Follow-up interviewers ask:**
- What is the difference between `exports` and `opens`?
- How do you migrate a legacy application to the module system?

### Q2. What are Collection factory methods introduced in Java 9?
**Difficulty:** Medium | Mid-Senior
**Type:** Theory + Tricky

**Answer:**
Java 9 added `List.of()`, `Set.of()`, and `Map.of()` / `Map.ofEntries()` for creating **immutable** collections concisely.

```java
// Java 9+ — immutable collections
List<String> list = List.of("A", "B", "C");
Set<Integer> set  = Set.of(1, 2, 3);
Map<String, Integer> map = Map.of("a", 1, "b", 2, "c", 3);

// Map with more than 10 entries — use ofEntries
Map<String, Integer> bigMap = Map.ofEntries(
    Map.entry("a", 1),
    Map.entry("b", 2),
    Map.entry("c", 3)
    // ... up to any size
);
```

**Key properties (tricky!):**
```java
List<String> list = List.of("X", "Y");

// 1. UnsupportedOperationException on any mutation
list.add("Z");    // throws UnsupportedOperationException
list.set(0, "A"); // throws UnsupportedOperationException

// 2. Null NOT allowed
List.of("A", null, "B"); // throws NullPointerException

// 3. Set.of() — no duplicate keys/values allowed
Set.of(1, 1); // throws IllegalArgumentException

// 4. Map.of() — no duplicate keys
Map.of("a", 1, "a", 2); // throws IllegalArgumentException

// 5. Iteration order for Set/Map is NOT guaranteed (unlike LinkedHashSet)
```

**Comparison with Arrays.asList:**
```java
List<String> asList = Arrays.asList("A", "B"); // fixed size but MUTABLE values
asList.set(0, "X");  // OK — set() works
asList.add("C");     // throws UnsupportedOperationException

List<String> listOf = List.of("A", "B");        // truly immutable
listOf.set(0, "X");  // throws UnsupportedOperationException
```

**Follow-up interviewers ask:**
- What's the difference between `Collections.unmodifiableList()` and `List.of()`?
- How do you create a mutable list from `List.of()`?

### Q3. What Stream enhancements were added in Java 9?
**Difficulty:** Medium | Senior
**Type:** Theory + Code

**Answer:**
Java 9 added four new Stream methods:

**1. `takeWhile(predicate)` — take elements while predicate is true, stop at first false:**
```java
// Unlike filter(), takeWhile STOPS at first non-matching element
List<Integer> nums = List.of(1, 2, 3, 4, 5, 1, 2);

List<Integer> result = nums.stream()
    .takeWhile(n -> n < 4)
    .collect(Collectors.toList());
// [1, 2, 3] — stops at 4, does NOT continue to find 1 and 2 at the end
```

**2. `dropWhile(predicate)` — drop elements while predicate is true, keep rest:**
```java
List<Integer> result = nums.stream()
    .dropWhile(n -> n < 4)
    .collect(Collectors.toList());
// [4, 5, 1, 2] — drops 1,2,3 (while < 4), keeps everything from 4 onwards
```

**3. `Stream.iterate(seed, hasNext, next)` — bounded iterate (no `limit()` needed):**
```java
// Java 8 — required limit()
Stream.iterate(0, n -> n + 2).limit(5).forEach(System.out::println); // 0,2,4,6,8

// Java 9 — built-in predicate (like a for loop)
Stream.iterate(0, n -> n < 10, n -> n + 2)
      .forEach(System.out::println); // 0, 2, 4, 6, 8
```

**4. `Stream.ofNullable(element)` — avoid null-check boilerplate:**
```java
String value = null;

// Java 8 — had to do this
Stream<String> s1 = value == null ? Stream.empty() : Stream.of(value);

// Java 9 — clean
Stream<String> s2 = Stream.ofNullable(value); // empty stream if null
Stream<String> s3 = Stream.ofNullable("hello"); // Stream["hello"]

// Real use case: flatMap with nullable values
List<String> names = Arrays.asList("Alice", null, "Bob", null, "Charlie");
List<String> nonNull = names.stream()
    .flatMap(Stream::ofNullable)
    .collect(Collectors.toList()); // [Alice, Bob, Charlie]
```

**Follow-up interviewers ask:**
- How does `takeWhile` differ from `filter` on an unordered stream?
- What is `Collectors.teeing()` (Java 12)?

### Q4. What Optional enhancements were introduced in Java 9–11?
**Difficulty:** Medium | Senior
**Type:** Theory + Code

**Answer:**

**Java 9 additions:**

**1. `ifPresentOrElse(consumer, runnable)` — handle both present and empty:**
```java
Optional<String> opt = Optional.of("Hello");

// Java 8
if (opt.isPresent()) System.out.println(opt.get());
else System.out.println("Empty");

// Java 9
opt.ifPresentOrElse(
    value -> System.out.println("Value: " + value),
    ()    -> System.out.println("Empty!")
);
```

**2. `or(supplier)` — return another Optional if empty:**
```java
Optional<String> primary   = Optional.empty();
Optional<String> secondary = Optional.of("fallback");

// Java 9 — or() returns another Optional (unlike orElse which returns T)
Optional<String> result = primary.or(() -> secondary);
System.out.println(result.get()); // fallback

// Use case: chaining multiple fallback sources
Optional<User> user = findInCache()
    .or(() -> findInDatabase())
    .or(() -> findInExternalService());
```

**3. `stream()` — convert Optional to Stream (0 or 1 element):**
```java
List<Optional<String>> optionals = List.of(
    Optional.of("A"), Optional.empty(), Optional.of("B"), Optional.empty(), Optional.of("C")
);

// Java 9 — flatMap with Optional.stream()
List<String> values = optionals.stream()
    .flatMap(Optional::stream)
    .collect(Collectors.toList());
// [A, B, C] — empties automatically filtered out
```

**Java 11 addition:**

**4. `isEmpty()` — complement of `isPresent()`:**
```java
Optional<String> opt = Optional.empty();
System.out.println(opt.isEmpty());     // true  (Java 11+)
System.out.println(opt.isPresent());   // false
```

**Follow-up interviewers ask:**
- How is `or()` different from `orElse()` and `orElseGet()`?
- When would you use `Optional.stream()` in practice?

### Q5. What is `var` (local variable type inference) in Java 10?
**Difficulty:** Medium | Senior
**Type:** Theory + Tricky

**Answer:**
Java 10 introduced `var` — a **reserved type name** (not a keyword) that lets the compiler infer the type of local variables from the initializer.

```java
// Before Java 10
Map<String, List<Employee>> deptMap = new HashMap<String, List<Employee>>();
Iterator<Map.Entry<String, Integer>> it = map.entrySet().iterator();

// Java 10+ — compiler infers the type
var deptMap = new HashMap<String, List<Employee>>();  // type: HashMap<String, List<Employee>>
var it = map.entrySet().iterator();                    // type: Iterator<Map.Entry<String, Integer>>

// Works with enhanced for-loop (Java 10)
for (var entry : map.entrySet()) {
    System.out.println(entry.getKey() + " = " + entry.getValue());
}

// Works with try-with-resources (Java 10)
try (var conn = DriverManager.getConnection(url)) {
    var stmt = conn.createStatement();
}
```

**Tricky rules and limitations:**
```java
// 1. var CANNOT be used without an initializer
var x;           // compile error — type cannot be inferred

// 2. var CANNOT be null (ambiguous type)
var x = null;    // compile error

// 3. var is for LOCAL variables only
class Demo {
    var field = "hello";  // compile error — fields not allowed
    
    public var method() { return "hi"; }  // compile error — return types not allowed
    
    public void test(var param) {}        // compile error — parameters not allowed
}

// 4. var with anonymous class — captures the anonymous type (useful!)
var obj = new Object() {
    String name = "anonymous";
    void greet() { System.out.println("Hello " + name); }
};
obj.greet();      // works! anonymous type is preserved
obj.name = "X";  // works! cannot do this with Object reference

// 5. var in lambda (Java 11) — allows annotations on lambda params
(@NotNull var s) -> s.toUpperCase();  // annotation requires explicit var
```

**Follow-up interviewers ask:**
- Does `var` affect performance?
- What is the actual type of `var x = List.of("a", "b")`?

### Q6. What new String methods were added in Java 11?
**Difficulty:** Easy-Medium | Mid-Senior
**Type:** Theory + Code

**Answer:**
Java 11 added several useful String methods:

```java
// 1. isBlank() — true if empty or contains only whitespace (includes Unicode whitespace)
"".isBlank();            // true
"   ".isBlank();         // true
"\t\n".isBlank();        // true
"  hello  ".isBlank();   // false
// Note: "   ".isEmpty() = false — isBlank is NOT the same as isEmpty

// 2. strip() / stripLeading() / stripTrailing() — Unicode-aware trim()
String s = "  hello  ";
s.strip();          // "hello"       — Unicode whitespace aware
s.stripLeading();   // "hello  "
s.stripTrailing();  // "  hello"
// trim() uses ASCII whitespace (char <= ' '), strip() uses Character.isWhitespace()
" hello ".strip();   // "hello"  (Unicode space)
" hello ".trim();    // " hello "  (NOT trimmed by trim)

// 3. lines() — splits string into stream of lines (handles \n, \r\n, \r)
"line1\nline2\nline3".lines()
    .forEach(System.out::println);
// line1
// line2
// line3

// Count lines
long count = "a\nb\nc".lines().count(); // 3

// 4. repeat(int count)
"ab".repeat(3);   // "ababab"
"*".repeat(10);   // "**********"
"-".repeat(0);    // ""
// Throws IllegalArgumentException if count < 0

// 5. Files.readString() / writeString() (Java 11)
import java.nio.file.*;

Path path = Path.of("test.txt");
Files.writeString(path, "Hello, Java 11!");
String content = Files.readString(path);
System.out.println(content); // Hello, Java 11!
```

**Follow-up interviewers ask:**
- Why was `strip()` added when `trim()` already exists?
- How is `lines()` different from `split("\n")`?

### Q7. What is the HTTP Client API introduced in Java 11?
**Difficulty:** Medium | Senior
**Type:** Theory + Code

**Answer:**
Java 11 standardized the `java.net.http` package with a modern, fluent HTTP Client that supports HTTP/1.1, HTTP/2, and WebSockets.

```java
import java.net.URI;
import java.net.http.*;
import java.time.Duration;

// Create client (reusable, thread-safe)
HttpClient client = HttpClient.newBuilder()
    .version(HttpClient.Version.HTTP_2)
    .connectTimeout(Duration.ofSeconds(10))
    .followRedirects(HttpClient.Redirect.NORMAL)
    .build();

// Synchronous GET request
HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.example.com/users"))
    .header("Accept", "application/json")
    .GET()
    .timeout(Duration.ofSeconds(30))
    .build();

HttpResponse<String> response = client.send(request, HttpResponse.BodyHandlers.ofString());
System.out.println(response.statusCode()); // 200
System.out.println(response.body());       // JSON string

// Asynchronous GET — returns CompletableFuture
CompletableFuture<HttpResponse<String>> futureResponse = client.sendAsync(
    request, HttpResponse.BodyHandlers.ofString()
);

futureResponse
    .thenApply(HttpResponse::body)
    .thenAccept(System.out::println)
    .join(); // block for demo

// POST with JSON body
HttpRequest postRequest = HttpRequest.newBuilder()
    .uri(URI.create("https://api.example.com/users"))
    .header("Content-Type", "application/json")
    .POST(HttpRequest.BodyPublishers.ofString("{\"name\":\"Alice\"}"))
    .build();

HttpResponse<String> postResponse = client.send(postRequest, HttpResponse.BodyHandlers.ofString());
```

**Follow-up interviewers ask:**
- How does this differ from Apache HttpClient or OkHttp?
- Can you send parallel requests with `HttpClient.sendAsync()`?

### Q8. What is the switch expression introduced in Java 14 (standard)?
**Difficulty:** Medium | Senior
**Type:** Theory + Code

**Answer:**
Java 12 added switch as a **preview feature**; it became standard in **Java 14**. The key changes:

**1. Arrow syntax — no fall-through, no break needed:**
```java
// Old switch statement — fall-through risk
String day = "MONDAY";
int numLetters;
switch (day) {
    case "MONDAY":
    case "FRIDAY":
    case "SUNDAY":
        numLetters = 6;
        break;
    case "TUESDAY":
        numLetters = 7;
        break;
    default:
        numLetters = -1;
}

// Java 14 switch EXPRESSION — concise, no fall-through
int numLetters = switch (day) {
    case "MONDAY", "FRIDAY", "SUNDAY" -> 6;
    case "TUESDAY"                    -> 7;
    case "THURSDAY", "SATURDAY"       -> 8;
    case "WEDNESDAY"                  -> 9;
    default -> throw new IllegalArgumentException("Unknown day: " + day);
};
```

**2. `yield` — return value from a block:**
```java
int result = switch (day) {
    case "MONDAY" -> {
        System.out.println("Start of work week");
        yield 1;  // yield returns value from block
    }
    case "FRIDAY" -> {
        System.out.println("End of work week");
        yield 5;
    }
    default -> 0;
};
```

**3. Switch expression must be exhaustive:**
```java
// Won't compile if default is missing (for non-enum types)
// For enums — if all constants covered, default not required
enum Season { SPRING, SUMMER, FALL, WINTER }

String desc = switch (season) {
    case SPRING -> "Warm";
    case SUMMER -> "Hot";
    case FALL   -> "Cool";
    case WINTER -> "Cold";
    // No default needed — all enum constants covered
};
```

**Follow-up interviewers ask:**
- What is the difference between `switch statement` and `switch expression`?
- When was `yield` introduced and why?

### Q9. What are Text Blocks (Java 15 standard)?
**Difficulty:** Easy-Medium | Mid-Senior
**Type:** Theory + Code

**Answer:**
Text blocks (Java 13 preview → Java 15 standard) allow multi-line string literals without manual escape sequences. The delimiter is `"""`.

```java
// Before Java 15 — ugly escape sequences
String json = "{\n" +
              "  \"name\": \"Alice\",\n" +
              "  \"age\": 30\n" +
              "}";

// Java 15 text block — clean, readable
String json = """
        {
          "name": "Alice",
          "age": 30
        }
        """;
// Leading spaces are stripped based on the position of the closing """
// Result: {"name":"Alice","age":30} with proper indentation

// HTML
String html = """
        <html>
            <body>
                <p>Hello</p>
            </body>
        </html>
        """;

// SQL
String query = """
        SELECT u.id, u.name, o.total
        FROM users u
        JOIN orders o ON u.id = o.user_id
        WHERE u.active = true
        ORDER BY o.total DESC
        """;
```

**Indentation handling:**
```java
// The trailing """ determines re-indentation
String s1 = """
        hello
        world
        """;        // no trailing spaces; re-indented by 8

String s2 = """
        hello
        world
""";                // trailing """ at col 0 — no indentation stripped

// Text block methods
String result = """
        Hello %s, you are %d years old.
        """.formatted("Alice", 30);
```

**Escape sequences in text blocks:**
```java
// \s — explicit space (prevents trailing whitespace removal)
// \<newline> — line continuation (suppress the newline)
String s = """
        This is a very long sentence that \
        continues on the next line.\s
        """;
```

**Follow-up interviewers ask:**
- How does text block indentation stripping work?
- What does `\s` mean in a text block?

### Q10. What are Records in Java 16 (standard)?
**Difficulty:** Medium | Senior
**Type:** Theory + Code

**Answer:**
Records (Java 14 preview → Java 16 standard) are **immutable data carrier classes** that eliminate boilerplate. The compiler auto-generates constructor, getters, `equals()`, `hashCode()`, and `toString()`.

```java
// Declare a record
public record Point(int x, int y) {}

// Generated by compiler:
// - canonical constructor: Point(int x, int y)
// - accessor methods: x(), y()  (NOT getX/getY)
// - equals(), hashCode(), toString()

Point p = new Point(3, 4);
System.out.println(p.x());          // 3   (accessor, not getX)
System.out.println(p.y());          // 4
System.out.println(p);              // Point[x=3, y=4]
System.out.println(p.equals(new Point(3, 4))); // true
```

**Customizing records:**
```java
public record Employee(String name, int age, String department) {
    
    // Compact canonical constructor (validation)
    public Employee {
        if (age < 0) throw new IllegalArgumentException("Age cannot be negative");
        name = name.trim();  // can normalize fields
    }
    
    // Additional methods
    public String nameAndDept() {
        return name + " (" + department + ")";
    }
    
    // Additional constructors must delegate to canonical
    public Employee(String name, int age) {
        this(name, age, "General");
    }
    
    // Static fields are allowed (instance fields are NOT)
    public static final String COMPANY = "Acme Corp";
}
```

**Records and interfaces:**
```java
// Records can implement interfaces
public interface Printable {
    void print();
}

public record Book(String title, String author) implements Printable {
    @Override
    public void print() {
        System.out.println(title + " by " + author);
    }
}

// Records are implicitly final — cannot be extended
// Records cannot extend other classes (already extends java.lang.Record)
```

**Records with generics:**
```java
public record Pair<A, B>(A first, B second) {
    public Pair<B, A> swap() {
        return new Pair<>(second, first);
    }
}

Pair<String, Integer> pair = new Pair<>("hello", 42);
System.out.println(pair.first());         // hello
System.out.println(pair.swap().first());  // 42
```

**Follow-up interviewers ask:**
- Can records be mutable?
- How do records handle inheritance?

### Q11. What is Pattern Matching for `instanceof` in Java 16?
**Difficulty:** Easy-Medium | Mid-Senior
**Type:** Theory + Code

**Answer:**
Pattern matching for `instanceof` (Java 14 preview → Java 16 standard) eliminates the redundant cast after an `instanceof` check.

```java
// Before Java 16 — tedious cast
Object obj = "Hello";
if (obj instanceof String) {
    String s = (String) obj;  // redundant cast
    System.out.println(s.length());
}

// Java 16 — pattern variable declared inline
if (obj instanceof String s) {
    System.out.println(s.length());  // s is automatically String
}

// Works with negation too
if (!(obj instanceof String s)) {
    System.out.println("Not a string");
} else {
    System.out.println(s.toUpperCase()); // s still in scope in else
}
```

**Combining with conditions:**
```java
// Can use the pattern variable in the same condition
if (obj instanceof String s && s.length() > 5) {
    System.out.println("Long string: " + s);
}

// But NOT with || (pattern variable not definitely assigned)
// if (obj instanceof String s || s.length() > 0) { } // compile error
```

**Real-world use case:**
```java
// Clean visitor-like pattern without casting
sealed interface Shape permits Circle, Rectangle, Triangle {}
record Circle(double radius) implements Shape {}
record Rectangle(double width, double height) implements Shape {}
record Triangle(double base, double height) implements Shape {}

double area(Shape shape) {
    if (shape instanceof Circle c)    return Math.PI * c.radius() * c.radius();
    if (shape instanceof Rectangle r) return r.width() * r.height();
    if (shape instanceof Triangle t)  return 0.5 * t.base() * t.height();
    throw new IllegalArgumentException();
}
```

**Follow-up interviewers ask:**
- What is Pattern Matching for switch (Java 17 preview)?
- How does this interact with sealed classes?

### Q12. What are Sealed Classes in Java 17 (standard)?
**Difficulty:** Medium-Hard | Senior
**Type:** Theory + Code

**Answer:**
Sealed classes (Java 15 preview → Java 17 standard) restrict which classes can **extend** or **implement** a class/interface. This enables exhaustive pattern matching and better domain modeling.

```java
// Sealed interface — only these three can implement it
public sealed interface Shape
    permits Circle, Rectangle, Triangle {}

// Each permitted subclass must be: final, sealed, or non-sealed
public final class Circle implements Shape {
    private final double radius;
    public Circle(double radius) { this.radius = radius; }
    public double radius() { return radius; }
}

public final class Rectangle implements Shape {
    private final double width, height;
    public Rectangle(double width, double height) {
        this.width = width; this.height = height;
    }
    public double width() { return width; }
    public double height() { return height; }
}

public non-sealed class Triangle implements Shape {
    // non-sealed — anyone can extend Triangle
}
```

**Why sealed classes?**

Before sealed classes, you couldn't exhaustively model a closed hierarchy. With sealed classes + pattern matching switch (Java 17 preview):

```java
// Java 17 — pattern matching for switch (preview)
double area(Shape shape) {
    return switch (shape) {
        case Circle c    -> Math.PI * c.radius() * c.radius();
        case Rectangle r -> r.width() * r.height();
        case Triangle t  -> 0; // placeholder
        // No default needed — compiler knows all cases via sealed
    };
}
```

**Rules:**
```java
// 1. Permitted classes must be in the same package (or same compilation unit)
// 2. Permitted classes must directly extend the sealed class
// 3. Every permitted class must be: final, sealed, or non-sealed

// Sealed with records (common pattern — Java 17+)
public sealed interface Result<T> permits Result.Success, Result.Failure {
    record Success<T>(T value) implements Result<T> {}
    record Failure<T>(String error) implements Result<T> {}
}

Result<String> result = new Result.Success<>("data");

String message = switch (result) {
    case Result.Success<String> s -> "Got: " + s.value();
    case Result.Failure<String> f -> "Error: " + f.error();
};
```

**Follow-up interviewers ask:**
- What is the difference between `final`, `sealed`, and `non-sealed` subclasses?
- How do sealed classes relate to the Algebraic Data Types concept?

### Q13. What is `Stream.toList()` added in Java 16?
**Difficulty:** Easy | Mid
**Type:** Theory + Tricky

**Answer:**
Java 16 added `Stream.toList()` as a convenient terminal operation — a shortcut for `Collectors.toList()`.

```java
List<String> names = List.of("Alice", "Bob", "Charlie");

// Java 8 way
List<String> upper = names.stream()
    .map(String::toUpperCase)
    .collect(Collectors.toList());

// Java 16 shortcut
List<String> upper = names.stream()
    .map(String::toUpperCase)
    .toList();
```

**Critical difference (tricky!):**
```java
// Collectors.toList() — returns a MUTABLE list (ArrayList)
List<String> mutable = names.stream().collect(Collectors.toList());
mutable.add("Dave"); // OK

// Stream.toList() — returns an UNMODIFIABLE list
List<String> immutable = names.stream().toList();
immutable.add("Dave"); // UnsupportedOperationException!

// Also: Stream.toList() ALLOWS null elements
// List.of() does NOT allow nulls — Stream.toList() does
List<String> withNull = Stream.of("A", null, "B").toList(); // OK
```

**Follow-up interviewers ask:**
- When would you still use `Collectors.toList()` over `Stream.toList()`?

### Q14. What are the Helpful NullPointerExceptions introduced in Java 14?
**Difficulty:** Easy | Mid
**Type:** Theory

**Answer:**
Java 14 improved NullPointerException messages to tell you **exactly which variable was null**.

```java
// Before Java 14 — unhelpful
```

### Q18. What is `instanceof` Pattern Matching for switch (Java 17 preview)?
**Difficulty:** Hard | Senior
**Type:** Theory + Code

**Answer:**
Java 17 introduced pattern matching for `switch` as a **preview feature** (standard in Java 21). It combines type pattern matching with switch expressions.

```java
// Traditional approach — if-else chain with instanceof
static String describe(Object obj) {
    if (obj instanceof Integer i)  return "int: " + i;
    if (obj instanceof String s)   return "string of length " + s.length();
    if (obj instanceof Double d)   return "double: " + d;
    if (obj == null)               return "null";
    return "unknown: " + obj.getClass();
}

// Java 17 preview — switch with type patterns
static String describe(Object obj) {
    return switch (obj) {
        case Integer i -> "int: " + i;
        case String s  -> "string of length " + s.length();
        case Double d  -> "double: " + d;
        case null      -> "null";  // null case in switch!
        default        -> "unknown: " + obj.getClass();
    };
}

// Guarded patterns — additional condition
static String categorize(Object obj) {
    return switch (obj) {
        case Integer i when i > 0 -> "positive int: " + i;
        case Integer i when i < 0 -> "negative int: " + i;
        case Integer i            -> "zero";
        case String s when s.isEmpty() -> "empty string";
        case String s  -> "string: " + s;
        default        -> "other";
    };
}

// With sealed classes — exhaustive, no default needed
sealed interface Expr permits Num, Add, Mul {}
record Num(int value) implements Expr {}
record Add(Expr left, Expr right) implements Expr {}
record Mul(Expr left, Expr right) implements Expr {}

static int eval(Expr expr) {
    return switch (expr) {
        case Num(var n)         -> n;  // record pattern (Java 21)
        case Add(var l, var r)  -> eval(l) + eval(r);
        case Mul(var l, var r)  -> eval(l) * eval(r);
        // No default — sealed hierarchy is exhaustive
    };
}
```

### Q19. What are compact constructors in Records?

### Q30. What are Virtual Threads (Project Loom) in Java 21?
**Difficulty:** Hard | Senior
**Type:** Theory + Scenario

**Answer:**
Virtual threads (Java 21, standard) are **lightweight threads** managed by the JVM, not the OS. They enable massive concurrency without the overhead of platform (OS) threads.

```java
// Platform thread (OS thread) — expensive
Thread platform = new Thread(() -> System.out.println("Platform thread"));
platform.start();

// Virtual thread (Java 21) — cheap (JVM-managed)
Thread virtual = Thread.ofVirtual().start(() -> System.out.println("Virtual thread"));

// Factory (preferred)
ThreadFactory factory = Thread.ofVirtual().factory();
Thread vt = factory.newThread(() -> System.out.println("From factory"));
vt.start();

// Executors.newVirtualThreadPerTaskExecutor() — one virtual thread per task
try (ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 1_000_000; i++) {  // 1 MILLION concurrent tasks!
        executor.submit(() -> {
            Thread.sleep(Duration.ofSeconds(1)); // blocks virtual thread, not OS thread
            return "done";
        });
    }
} // auto-close waits for all tasks
```

**How it works:**
- Virtual threads are **mounted** on a platform thread (carrier thread) from a fork-join pool
- When a virtual thread blocks (I/O, sleep, lock), it **unmounts** — carrier thread is free
- When unblocked, it remounts on any available carrier thread
- Result: millions of virtual threads on a handful of platform threads

**Key differences from platform threads:**

| Aspect | Platform Thread | Virtual Thread |
|--------|----------------|----------------|
| Creation cost | ~1MB stack, OS resource | ~1KB, JVM heap |
| Max practical count | ~thousands | millions |
| Blocking | Blocks OS thread | Unmounts (no blocking) |
| ThreadLocal | OK | Use with care — per-VT but millions of them |
| Pool | Use thread pools | One VT per task (no pooling needed) |

**When NOT to use virtual threads:**
```java
// CPU-bound tasks — virtual threads don't help
// (Virtual threads are great for I/O-bound work)

// synchronized block pins the virtual thread (Java 21)
// — carrier thread is blocked too (called "pinning")
synchronized (lock) {
    Thread.sleep(1000); // pins carrier thread — bad for virtual threads!
}

// Use ReentrantLock instead
lock.lock();
try {
    Thread.sleep(1000); // virtual thread unmounts correctly with ReentrantLock
} finally {
    lock.unlock();
}
```

**Follow-up interviewers ask:**
- How do virtual threads differ from reactive programming (WebFlux)?
- What is "thread pinning" and why is it a problem?

Record patterns (Java 21 standard) allow deconstructing record components directly in `instanceof` and `switch`.

```java
record Point(int x, int y) {}
record Circle(Point center, double radius) {}

// Nested record pattern
Object obj = new Circle(new Point(1, 2), 5.0);

// instanceof with record pattern — destructures automatically
if (obj instanceof Circle(Point(int x, int y), double r)) {
    System.out.println("Circle at (" + x + "," + y + ") r=" + r);
    // Circle at (1,2) r=5.0
}

// switch with record pattern (Java 21)
static String describe(Object obj) {
    return switch (obj) {
        case Point(int x, int y)                   -> "Point(" + x + "," + y + ")";
        case Circle(Point(int x, int y), double r)  -> 
            "Circle at (" + x + "," + y + ") radius " + r;
        default -> "unknown";
    };
}

// Guarded record pattern
static String classify(Object obj) {
    return switch (obj) {
        case Circle(Point(int x, int y), double r) when r > 10 -> "large circle";
        case Circle(Point(int x, int y), double r)             -> "small circle";
        case Point(int x, int y) when x == 0 && y == 0        -> "origin";
        case Point(int x, int y)                               -> "point";
        default -> "unknown";
    };
}
```
